# Admin interface

On first run, `/admin` asks for an admin access key when the server has no
administrators. After registration and reload, it shows "I want to run a:"
if neither `isSetupComplete: true` nor a `defaultModule` is configured.
Registering an administrator alone does not complete server setup. A configured
default module opens Overview. Choosing "Existing Node" saves
`isSetupComplete: true` in the server options, then opens Overview after the save
succeeds. This survives page reloads, other browsers, and server restarts while
preserving the node's existing configuration. Local Dev and Full/Mainnet setup
also save this completion flag with the selected configuration.

The setup screen starts with Existing Node, Local Dev Node, and Full/Mainnet Node,
with descriptions below each button. Choosing Local Dev or Full/Mainnet reveals
the root-module buttons without saving anything. Clicking a root module saves
the selected node type and default module, then shows its recompile instructions.
While saving, further choices are disabled. A failed save restores the choices
so the user can retry or change the node type and module.

Registration, admin validation, and setup saving display both server and transport
errors. Failed registration and setup saving restore their controls for retry.

Admin waits up to five seconds for the configured server connection, then tries
`/wsopen` at the current page's host and port (`wss` on HTTPS, `ws` on HTTP).
This uses Saito's normal connector and does not change saved configuration.
Registration stays disabled until the expected server completes its handshake.
If the fallback has not completed that handshake after eight more seconds, the
intro shows endpoint configuration guidance and links to the
[network configuration wiki](https://wiki.saito.io/config/network). A later
successful connection enables registration; disconnection disables it again.

Status notifications and alert dialogs use the Admin light/dark theme.

The sidebar lists Overview, Network (peer connections), Modules, Administrators,
Database, Blocks, Mempool, and Faucet when available. Navigation and theme
icons sit at the bottom of the sidebar; the sidebar scrolls on short screens.

Network shows read-only Local IP and Local port values from `server.host` and
`server.port` above the public address form. Missing values appear as a dash.
Updating the public address changes `server.endpoint` while preserving the local
server address and protocol.

Modules supports general search across names, descriptions, categories, status,
and class, plus category/status/class selectors. "Has description" and "Has
image" are checked by default; uncheck them to include modules missing those
fields. Filters combine and only affect visibility, so saving retains the modes
of hidden modules. Search and filter choices survive saves and navigation within
the current page session.

The server reads literal constructor metadata without loading disabled modules.
Thumbnails use a declared local `img` when available, or standard module images
such as `web/img/arcade/arcade.jpg`, `saito_icon`, and `web/img/<module>.*`.
Admin serves these images even when the module is disabled. Cards keep their
existing dimensions; a missing or failed image leaves a plain blank thumbnail.

The sidebar’s moon/sun button switches the entire admin interface between
light and dark. Light is the default. The choice is stored in this browser under
`saito-admin-theme` and applied before styles load. If browser storage is blocked,
the switch still works for the current page. This preference is independent of
other Saito modules and does not change server configuration.

The sidebar toolbar shows a back arrow only when the Navigation API exposes a
previous history entry on the same host. Clicking it goes back in browser history.
Otherwise it shows a small Saito icon linking to `/`, including in older browsers
that cannot expose history URLs. The toolbar updates after history navigation;
the destination is checked again when clicked.

Edit styles in `web/css/`; `web/style.css` is generated by the normal Node build.

Overview includes a Three.js network diagram of the managed server and its
currently connected peers. With one connected peer, this node appears at the top
and its peer below; larger networks keep this node at the center. The local label
uses the same server public key as the overview information above. Full nodes (`synctype: full`) have two parallel arrows
in opposite directions; browsers (`synctype: lite`) have one line. Labels include
the complete public key and advertised URL, or the transport IP when no URL is
available. An unavailable address is explicitly marked. Transport IPs can belong
to a reverse proxy; forwarded headers are not treated as verified client IPs.
The authenticated `list-peers` response includes this transport address as `ip`.

The Network page ends with a collapsed "Peer diagnostics — raw Rust state"
section. Opening it requests an unfiltered server snapshot through the
authenticated `get-peer-diagnostics` request; Refresh snapshot captures it again.
This uses the existing `app.core.network.peers.get()` binding and includes every
Rust peer entry, preserving duplicate identities and unverified/disconnected
entries. JSON represents Maps as `[key, value]` pairs, BigInts as decimal strings,
and byte arrays as arrays. This is the server's Rust state at capture time, not
the browser's peer list or the JS socket registry.

Connections load when Overview opens and when Refresh is clicked. Disconnected
and connecting peers are excluded. The heading, legend, status, and Refresh button
sit over the diagram. The diagram scales to the available viewport height with a
600px minimum, including on resize. The camera fits the nodes inside the box;
node labels keep their fixed text size and lower-right offsets. Without WebGL, the labels remain available.
Leaving Overview releases the scene and resize listeners.

Public keys in the server information and network labels use an ellipsis when
space is limited; hovering reveals the full key. Copying retains the full key.
The server public key is displayed without a border, with a copy button and
success/failure feedback. Copying uses the Clipboard API with a selection-copy
fallback for HTTP nodes or browsers that deny clipboard access.
