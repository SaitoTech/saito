# Conquest — Field Atlas

The visual direction is a mid-century travel atlas: warm paper, charcoal typography, loosely brushed pigment, generous editorial whitespace and small cartographic annotations. A compact right-hand command panel keeps every turn on the board. Territory fills encode ownership, badges encode armies, and outlines encode interaction. Shapes and player names reinforce color so play does not depend on color alone.

The board is an SVG built from the engine's independent territory geometry. CSS custom properties define paper, ink, pigment, player colors and typography; no game logic depends on the theme. A separate Three.js scene gives combat tactile dice, with reduced-motion support. Changing the visual direction requires replacing the stylesheet and optional map geometry, not changing the rules or network protocol.

Neighbouring mainland territories share vertices so a thin paper stroke creates even country gaps. Wider channels and colored coast outlines distinguish continents; map labels show each continent's reinforcement bonus, with control-progress badges in the field guide. Cards reuse territory silhouettes with separate infantry, cavalry and artillery icons. The layout reserves a bottom row for all players, scales the board to the remaining space, and lets the command panel scroll independently. The enlarged map supports dragging without triggering territory actions. Troop sliders begin at the maximum legal count for quick deployment and movement.

Interaction: choose an origin, then an adjacent target. Phase-aware controls show the next legal action, army counts, optional blitz, a card set selector, and a clear end-phase button. Setup and reinforcements support one-click placement. Conquests make the required troop move explicit; fortification supports adjacent friendly territories. Neutral armies have a distinct hatched treatment in two-player games. A player roster, phase track, concise turn journal and rules sheet explain the current state without obscuring the board.

The standalone page is a local hotseat demonstration using exactly the same engine and UI as the Saito module. The module supplies a controller with `getState()`, `dispatch(action)`, `getPlayer()`, and `getPlayerName(id)`; it remains responsible for Saito turn queues and deterministic randomness. `getPlayer() === 0` enables hotseat input in the demonstration only.
