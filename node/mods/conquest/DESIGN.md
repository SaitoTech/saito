# Conquest — Field Atlas

The visual direction is a mid-century travel atlas: warm paper, charcoal typography, loosely brushed pigment, generous editorial whitespace and small cartographic annotations. A right-hand command panel keeps every turn on the board. Territory fills encode ownership, badges encode armies, and outlines encode interaction. Shapes and player names reinforce color so play does not depend on color alone.

The shared overlay and invite artwork (`web/img/cover.svg`) contains no visible text: a centered pigment-colored world map sits behind charcoal cannon, infantry and cavalry silhouettes matching the card unit symbols.

Battle dice use each participating player's exact palette colour, with glossy faces and contrasting pips. Dice panels have transparent backgrounds with no shadow. Colours follow the attacker and defender recorded before each roll, including a muted neutral defender. The flat fallback uses the same colours.

The board is an SVG built from the engine's independent territory geometry. CSS custom properties define paper, ink, pigment, player colors and typography; no game logic depends on the theme. Two Three.js dice groups stay in the open Pacific water below Alaska and west of Chile, with reduced-motion and non-WebGL support. They overlay that fixed region of the map, so combat never resizes or moves the board. Battle dice use each participating player's exact palette colour. The dice and the army counts on the map show the result; no separate casualty line is drawn under the dice. The compass and Pacific label are hidden while the dice are showing. Both groups render before rolling, and the animation clock starts on its first frame. Every roll in a blitz plays before its losses are subtracted. The first roll uses an 820 ms spin and an 800 ms pause; each following roll shortens both, down to 160 ms and 90 ms. A single attack keeps the original pace. Every participant and observer sees the same sequence. Changing the visual direction requires replacing the stylesheet and optional map geometry, not changing the rules or network protocol.

Neighbouring mainland territories share vertices so a thin paper stroke creates even country gaps. Wider channels and colored coast outlines distinguish continents; map labels show each continent's reinforcement bonus, with control-progress badges in the field guide. Cards reuse territory silhouettes with separate infantry, cavalry and artillery icons. The layout reserves a short bottom row for equal player panels and gives the remaining viewport to the map. The desktop command panel is 250px wide, or 220px below 1200px, and turn details use its height above content-sized notices and actions, scrolling only when needed. Each panel shows an identicon, name, and four icon counts: territories, armies, next-turn reinforcement income, and cards. Your card count opens the card overlay. The next set bonus stays in the sidebar prompt, not on the panel. A playable set adds a sidebar prompt. A themed board sizer beside the hamburger scales the map within its viewport; center restores its fitted size. Enlarged maps support mouse and touch dragging without triggering territory actions. Troop sliders begin at the maximum legal count for quick deployment. Fortification chooses a source and destination on the map, then a compact overlay previews the resulting army counts and starts with every army moved except the one that must stay behind. When the source has exactly two armies, that single spare army moves immediately and the slider is not shown.

Interaction: choose an origin, then an adjacent target. Phase-aware controls show the next legal action, army counts, a remembered Steamroll option, clickable cards that automatically trade a valid selected set of three, and a clear Finish attacking button. Moving armies or skipping movement advances the turn immediately. An impossible attack or movement phase displays its reason for two seconds, then advances automatically; the pause waits for battle playback and pending card work. All viewers see the notice, while only the active player sends the phase-ending move. Controls use the active player’s colour. Setup and reinforcements support one-click placement. Conquests place the occupation choice on the map. The slider appears only when more than one legal amount exists, starts at the maximum, and previews both army counts until Advance confirms the existing occupation action. A single legal amount advances automatically. Steamroll still advances all but one army inside the attack; fortification supports adjacent friendly territories. Neutral armies have a distinct hatched treatment in two-player games. A player roster uses each faction color for its accent and border. The player taking the current turn is marked by filling that player's name region with the same faction color, without a YOU badge or TURN label. A dispatch journal that closes on outside clicks and rules sheet explain the current state without obscuring the board. The Conquest wordmark, in the muted header grey, shares the existing Saito menu row; Field guide is in the Game menu. The bottom bar holds the player panels. The native game menu, wallet drawer and dispatch log share the atlas paper, ink, typography and subtle borders, with active-player accents; these styles apply only while Conquest is mounted. Attack and Blitz buttons beside a selected target sit together on a cream angled backplate and use the same dice and Steamroll settings as the panel. Attack fights one round; Blitz repeats until the territory falls or the attacker must stop. Steamroll is a larger checkbox in the command panel. It advances every army except one and then selects the conquered territory. That choice is a saved game preference and stays across turns. Shift-click on an attack target blitzes and steamrolls that combat only, using the maximum attack dice, without changing the saved checkbox.

The standalone page is a local hotseat demonstration using exactly the same engine and UI as the Saito module. The module supplies a controller with `getState()`, `dispatch(action)`, `getPlayer()`, and `getPlayerName(id)`; it remains responsible for Saito turn queues and deterministic randomness. `getPlayer() === 0` enables hotseat input in the demonstration only.

Readability: board text is restored to its original sizes, including the 12px screen minimum for scaled labels. Elsewhere, the enlarged text is reduced by 33%, with a 12px minimum. The turn status is one line, in the existing status type, naming whose turn it is and the current phase. Player panels share one compact height and equal widths along the bottom. Narrow and short screens scroll rather than shrinking controls. Card faces have larger territory art, names and unit symbols. The redundant identity header is removed. The bar-chart shortcut inside the turn-status badge and the Stats menu open a themed dialog with per-player combined attack/defense dice histograms, casualties, battle outcomes, earned armies and territory gains/losses, filtered by all campaigns or the campaign number shown in the header. Every attack has its own losses/defeated dispatch. Statistics are recorded by the deterministic rules engine, never by animation or rendering.
